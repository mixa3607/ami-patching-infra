# IMB760 BIOS Mod Tools

Набор исходников, извлеченных компонентов и утилит для исследования и сборки
модифицированных прошивок материнской платы Axiomtek IMB760 / Depo DPC627-A.
Репозиторий охватывает BIOS (AMI Aptio и EDK2) и BMC (AMI MegaRAC SP и
OpenBMC).

Проект предназначен для экспериментального стенда. Неправильная сборка или
прошивка может сделать BIOS или BMC неработоспособными. Перед записью всегда
проверяйте совместимость образа с платой, сохраняйте исходный дамп и
используйте проверенный способ восстановления.

## Целевая платформа

Репозиторий рассчитан на Axiomtek IMB760, также поставлявшуюся как Depo
DPC627-A. Это двухсокетная серверная плата LGA4189 P4 со следующими важными для
прошивок свойствами:

- BIOS и BMC хранятся в отдельных 32 MiB SPI flash `W25Q256JVFQ`;
- BMC построен на ASPEED AST2500;
- поддерживаются RDIMM и LRDIMM; UDIMM на проверенном стенде не запускаются;
- проверен запуск с инженерными процессорами Intel 4-6 stepping;
- для питания необходимы 24-pin ATX и два 8-pin CPU; остальные разъемы питания
  опциональны.

Известные исходные семейства прошивок:

| Компонент | Базовая прошивка | Модификация в репозитории |
| --- | --- | --- |
| BIOS | Axiomtek AMI Aptio IMB760 V1.00, release 5.21 | `AMI/` |
| BIOS | Depo TianoCore EDK2 v1.0 | `EDK2/` |
| BMC | AMI MegaRAC SP 2.02.76714 | `MEGARACSP/` |
| BMC | Depo OpenBMC 1.0.1 для DPC627-A | `OPENBMC/` |

Образы BIOS и BMC, а также семейства AMI, EDK2, MegaRAC SP и OpenBMC можно
комбинировать, но такие конфигурации могут давать нестабильную загрузку.
Одинаковый размер SPI flash не означает совместимость образов или таблиц
разделов.

## Требования

Для контейнерных сборок необходимы:

- Linux с Bash и Git;
- Docker с поддержкой Buildx;
- доступ к сети: Dockerfile загружает зафиксированные зависимости во время
  сборки;
- достаточно свободного места для образов Docker и артефактов прошивки.

Утилиты вне Docker требуют Python 3. Состав сторонних UEFI-инструментов и
ссылки на их источники перечислены в [`SOFTWARE/readme.md`](SOFTWARE/readme.md).

## Быстрый старт

Клонируйте репозиторий с двоичными файлами и убедитесь, что Docker доступен:

```sh
git clone <repository-url>
cd bios-mod-tools
docker buildx version
```

### AMI BIOS

Соберите модифицированный образ из корня репозитория:

```sh
./AMI/build-docker.sh
```

Результат создается в
`AMI/build/<git-tag-or-short-sha>/IMB760_BIOS_AMI_mixa3607_mod-<version>.rom`.
Скрипт выводит SHA-256 готового файла. Для явного имени каталога сборки можно
задать `REPO_GIT_REF`:

```sh
REPO_GIT_REF=local-test ./AMI/build-docker.sh
```

Флоу изменения IFR и описание автоматизированной прошивки через EFI Shell
приведены в [`AMI/readme.md`](AMI/readme.md). Параметры AFUEFI не выбираются
скриптом: использовать можно только параметры, проверенные для конкретной
версии AFUEFI и платы.

### MegaRAC SP BMC

Перед сборкой задайте MAC-адрес и двухзначный суффикс версии:

```sh
printf '%s\n' 'DE:AD:BE:EF:EE:EF' > MEGARACSP/eth-mac.txt
printf '%s\n' '01' > MEGARACSP/version.txt
./MEGARACSP/build-docker.sh
```

Готовый 32 MiB образ находится в
`MEGARACSP/build/<git-tag-or-short-sha>/IMB760_BMC_mixa3607_mod-<version>-<git-tag-or-short-sha>.bin`.
Подробности о native KVM, `bak2shell`, разбиении базового образа и локальных
тестовых образах находятся в [`MEGARACSP/README.md`](MEGARACSP/README.md).

### EDK2 BIOS

`EDK2/` содержит базовый дамп, описания заменяемых разделов, микрокоды и
полученные артефакты сборки. Переменные окружения и имена файлов определены в
[`EDK2/env.sh`](EDK2/env.sh). После подготовки образа можно сравнить состав
микрокодов исходного и измененного BIOS:

```sh
cd EDK2
./render-mcodes.sh
```

## BIOS State Lab

[`tools/bios-state-lab/`](tools/bios-state-lab/) - Python-инструмент для
исследования IFR и переменных UEFI. Он строит реестр настроек по извлеченному
IFR, создает снимки переменных, вычисляет статическое состояние пунктов меню и
формирует ограниченные запросы для bridge-драйвера.

Пример построения реестра:

```sh
cd tools/bios-state-lab
python3 bios_state_lab.py build-registry ../../AMI/EXTRACTED registry.json
```

Команды `write` и `restore` работают с переменными EFI на целевой машине и
требуют `root`. Не используйте их с Secure Boot, паролями или произвольными
переменными. Полный проверенный сценарий находится в
[`tools/bios-state-lab/EXAMPLES.md`](tools/bios-state-lab/EXAMPLES.md).

## CI

GitHub Actions автоматически собирает артефакты:

- AMI BIOS при изменениях в `AMI/` или по тегам `A1_*`;
- MegaRAC SP BMC при изменениях в `MEGARACSP/`, по тегам `N1_*` или вручную.

Workflow MegaRAC SP при ручном запуске принимает необязательный MAC-адрес и
загружает готовый образ как artifact. Артефакты обоих workflow хранятся 30 дней.

## Проверка перед прошивкой

1. Сверьте имя платы, тип прошивки и размер итогового образа с исходным дампом.
2. Проверьте SHA-256, выведенный скриптом сборки, и сохраните его вместе с
   образом.
3. Сохраните рабочий дамп BIOS или BMC и подготовьте способ восстановления.
4. Не прерывайте питание платы во время записи SPI flash.
5. После первой загрузки проверьте доступ к BMC и основные функции хоста до
   дальнейших изменений.

## Прошивка и восстановление

Для обеих SPI flash подходит аппаратное чтение и запись программатором с
прищепкой, без выпаивания микросхемы. Это также основной путь восстановления
неработоспособной платы.

Для AMI Aptio BIOS возможна программная запись через AFUEFI; этот способ не
применим к EDK2. Для EDK2 на текущем стенде проверен только аппаратный способ.
Сценарий подготовки AFUEFI в EFI Shell описан в
[`AMI/readme.md`](AMI/readme.md).

Для BMC используйте ASPEED iRMP SoC Flash, запускаемый на хостовой ОС. Он
работает с BMC, в том числе если его штатная прошивка не загружается. Перед
заменой BMC-образа учитывайте, что MAC-адрес задается прошивкой или ее
окружением U-Boot; после записи проверьте получение адреса по DHCP и MAC в
IPMI-канале 1.

Прошить BIOS через BMC невозможно: линии от BMC к SPI flash BIOS на плате не
разведены. Для BIOS используйте AFUEFI (только AMI Aptio) или программатор.

## Статус и ограничения

- В репозитории присутствуют извлеченные вендорские компоненты и двоичные
  образы; применимость и условия их использования необходимо проверять
  отдельно.
- Базовые образы и патчи рассчитаны на IMB760 / DPC627-A. Они не являются
  универсальными для других плат, даже при похожей платформе.
- Наличие записи UEFI-переменной не гарантирует, что настройка сохранится или
  повлияет на оборудование после POST. BIOS State Lab следует использовать для
  повторяемых экспериментов со снепшотами и проверкой после перезагрузки.
