# IFR data

Required structure (auto-generated by `extract-ifr-sections.sh` from a clean BIOS dump):

```
├── Section_PE32_image_AMITSE_AMITSE.sct         # AMITSE PE32 section (from UEFITool)
├── Section_Freeform_subtype_GUID_setupdata_..._body.bin  # setupdata body (from UEFITool)
├── [<name>]  # any name / repeat
│   ├── <guid>.guid            # section guid from UEFITool
│   ├── <name>_setup.sct       # patched sct (generated by build-ver.sh)
│   ├── data.json              # data.json from UEFI-Editor / All changes must be applied to it
│   └── orig
│       ├── <name>_setup.sct       # clean PE32 section from the dump
│       ├── <name>_ifr.txt         # IFRExtractor-RS verbose output
│       └── data.json              # data.json from UEFI-Editor / orig
```

## Workflow (no browser needed for patching)

1. Dump BIOS, run:
   ```sh
   ./extract-ifr-sections.sh IMB760_BIOS.bin
   ```
   This regenerates `IFR/` with clean (orig) `.sct`, AMITSE, setupdata and
   `_ifr.txt` for every form.
2. (Optional, once) Generate `data.json` per form in UEFI-Editor from the clean
   files, or keep existing `data.json`.
3. Edit `data.json` (unsuppress items / access levels), see `data.md`.
4. Run `build-ver.sh` — it patches the clean `orig/*.sct` + `setupdata` with the
   CLI (`SOFTWARE/uefi-editor-cli`) and injects everything into the BIOS dump.

The `uefi-editor-cli` reproduces the browser "UEFI files" export byte-for-byte:

```sh
node ../../SOFTWARE/uefi-editor-cli/index.mjs sct \
  --setup IFR/Setup/orig/Setup_setup.sct \
  --data IFR/Setup/data.json -o out/Setup.sct
node ../../SOFTWARE/uefi-editor-cli/index.mjs setupdata \
  --setupdata IFR/Section_..._setupdata_..._body.bin \
  --data IFR/Setup/data.json --data IFR/Platform/data.json ... -o out/setupdata.bin
node ../../SOFTWARE/uefi-editor-cli/index.mjs verify \
  --setup <orig sct> --amitse <orig amitse> --setupdata <orig setupdata> \
  --data <data.json>
```
